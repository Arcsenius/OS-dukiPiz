# Типовые задачи лабораторных работ по ОС

Исходники написаны на C для Unix/POSIX (Linux и macOS). В методичках варианты выдаёт преподаватель. Здесь реализованы **вариант 1 лабораторной №1** и **вариант 17 лабораторной №2** как типовые примеры работы с процессами и потоками.

## Лабораторная №1: родительский и дочерний процессы

Файлы: `lab1/sum_parent.c`, `lab1/sum_child.c`.

Родитель считывает первой строкой путь к выходному файлу, создаёт два неименованных канала и запускает отдельную программу `sum_child`. Первый канал становится стандартным вводом дочернего процесса, второй — его стандартным выводом. Каждая следующая строка родителя содержит произвольное количество `int`. Дочерний процесс проверяет числа, суммирует их и пишет по одному результату на строку в файл. По обратному каналу он отвечает `OK` или `ERROR`. Неверная строка не прерывает обработку следующих строк. Для суммы используется `long long`, чтобы сумма нескольких корректных `int` не переполняла `int`; переполнение `long long` проверяется.

```sh
make
cd lab1
printf 'result.txt\n1 2 3\n-5 2 10\n' | ./sum_parent
cat result.txt
```

Ожидаемое содержимое `result.txt`: строки `6` и `7`. После ввода имени файла в интерактивном режиме можно вводить строки с числами; завершение ввода — Ctrl-D.

Схема: `клавиатура → parent → pipe → child → файл`, ответы: `child → pipe → parent → экран`.

## Лабораторная №2: ограниченное число потоков

Файл: `lab2/minmax.c`.

Программа создаёт воспроизводимый массив целых чисел, вычисляет минимум и максимум последовательно и параллельно, проверяет совпадение результатов. Ключ `-t` задаёт **максимальное** число рабочих потоков: фактически создаётся `min(-t, длина массива)` потоков. Каждый обрабатывает свой непересекающийся отрезок и записывает результат в собственную структуру. `pthread_join` дожидается завершения всех потоков до объединения локальных результатов; гонки записи в общую переменную нет.

```sh
./lab2/minmax -n 10000000 -t 4 -r 5
```

`-n` — число элементов, `-t` — предел рабочих потоков, `-r` — количество повторов. Печатаются PID, фактическое число рабочих потоков, найденные минимум и максимум, лучшие времена последовательного и параллельного запусков, ускорение и эффективность. Время создания и ожидания потоков входит в параллельное измерение. Инициализация массива в замер не входит. Из-за накладных расходов и пропускной способности памяти параллельный вариант может оказаться медленнее, особенно на небольшом массиве.

Для демонстрации количества потоков во время работы запустите:

```sh
./lab2/minmax -n 10000000 -t 4 -r 1 --hold-ms 5000 &
pid=$!
ps -M -p "$pid"          # macOS: строки для потоков процесса
wait "$pid"
```

В Linux вместо `ps -M` используйте `ps -T -p "$pid"`. Опция `--hold-ms` нужна только для наблюдения потоков: она добавляет задержку каждому работнику и **не годится для замеров**. Кроме рабочих потоков ОС показывает основной поток.

### Что включить в отчёт по лабораторной №2

Проведите серию запусков без `--hold-ms`, например для `n = 10^5, 10^6, 10^7` и `t = 1, 2, 4, 8`. Для каждого случая запишите последовательное время `T₁`, параллельное время `Tₚ`, ускорение `S = T₁ / Tₚ`, эффективность `E = S / p`, где `p` — фактически созданное число рабочих потоков. Сравнивайте запуски на одной машине без другой тяжёлой нагрузки. Объясните, почему при малом массиве затраты на `pthread_create`/`pthread_join` преобладают, а при большом ускорение может ограничиваться скоростью памяти.

## Глоссарий функций C и POSIX

| Функция | Заголовок | Для чего нужна здесь |
|---|---|---|
| `getline` | `<stdio.h>` (POSIX) | Считывает строку произвольной длины; память при необходимости расширяется. Возвращает длину или `-1`. |
| `fopen`, `fclose` | `<stdio.h>` | Открывают и закрывают файл со стандартной буферизацией. |
| `fprintf`, `printf`, `puts`, `fputs` | `<stdio.h>` | Выводят форматированный текст или строки в файл, канал или терминал. |
| `fwrite`, `fflush` | `<stdio.h>` | Передают байты и принудительно отправляют буферизированные данные в канал/файл. |
| `fdopen` | `<stdio.h>` (POSIX) | Создаёт `FILE *` из файлового дескриптора канала. |
| `strtol`, `strtoumax` | `<stdlib.h>`, `<inttypes.h>` | Преобразуют текст в целое число; вместе с `errno` и указателем конца позволяют проверять ошибки ввода. |
| `malloc`, `calloc`, `free` | `<stdlib.h>` | Выделяют, обнуляют и освобождают динамическую память. |
| `pipe` | `<unistd.h>` | Создаёт канал: `fd[0]` для чтения, `fd[1]` для записи. |
| `fork` | `<unistd.h>` | Создаёт дочерний процесс; в ребёнке возвращает `0`, в родителе — PID. |
| `dup2` | `<unistd.h>` | Перенаправляет дескриптор, например канал на `stdin` или `stdout`. |
| `execl` | `<unistd.h>` | Заменяет код дочернего процесса другой программой. При успехе не возвращается. |
| `close` | `<unistd.h>` | Закрывает ненужный файловый дескриптор; это важно и для корректного наступления EOF в канале. |
| `open`, `read`, `write` | `<fcntl.h>`, `<unistd.h>` | Небуферизованная работа с файлом или каналом через дескриптор; может понадобиться в других вариантах. |
| `mkfifo` | `<sys/stat.h>` | Создаёт именованный канал, если вариант требует обмена через путь в файловой системе. |
| `waitpid` | `<sys/wait.h>` | Ожидает конкретный дочерний процесс; `WIFEXITED` и `WEXITSTATUS` проверяют его завершение. |
| `_exit` | `<unistd.h>` | Немедленно завершает дочерний процесс при ошибке до/после `exec`, без повторной очистки буферов родителя. |
| `signal` | `<signal.h>` | Здесь отключает аварийное завершение родителя по `SIGPIPE`, чтобы обработать ошибку записи в закрытый канал. |
| `pthread_create`, `pthread_join` | `<pthread.h>` | Создают рабочий поток и ожидают его завершения; `join` также обеспечивает видимость записанных им результатов. |
| `pthread_mutex_init`, `pthread_mutex_lock`, `pthread_mutex_unlock`, `pthread_mutex_destroy` | `<pthread.h>` | Защищают общие данные, когда несколько потоков действительно изменяют одну структуру. В примере min/max не нужны: каждый поток пишет в свой `Job`. |
| `clock_gettime` | `<time.h>` | Измеряет время монотонными часами `CLOCK_MONOTONIC`, не зависящими от перевода системных часов. |
| `nanosleep` | `<time.h>` | В демонстрационном режиме задерживает поток, чтобы его было видно в `ps`. |
| `perror`, `strerror` | `<stdio.h>`, `<string.h>` | Превращают код системной ошибки в понятное сообщение. |

`pipe`, `fork`, `dup2`, `exec`, `waitpid` и `pthread_*` — интерфейсы POSIX, а не часть стандартного ISO C. Для Windows потребуются аналоги: `CreateProcess`, `CreatePipe`, `WaitForSingleObject`, `CreateThread`/`WaitForSingleObject` или другой потоковый API.
